# ANA — 2026-10-03 — URL de firma con localhost

El correo de firma usaba `http://localhost:5173` porque el API no tenía
`FRONT_URL` y el fallback era el Vite de desarrollo.

El front manda `window.location.origin` en `POST /sales/:id/sign-link`.
El API arma `/firmar/{token}` con esa URL. No hace falta `.env`.

# ANA — 2026-10-03 — Corrección desde Mesa de Control

`PATCH /api/integrations/odoo/sales/:id/correction` guarda los campos
marcados y pone la venta en `PENDING_CORRECTION`. El vendedor responde
con `POST /api/sales/:id/correction` y vuelve al estatus anterior.

En producción, antes de desplegar:

`ALTER TABLE sales ADD COLUMN IF NOT EXISTS correction_request text NOT NULL DEFAULT '';`

# ANA — 2026-10-05 — Enlace de firma sin URL en el body

En producción `POST /sales/:id/sign-link` respondía 400 si no venía
`frontUrl`. El API ahora toma el origen de `frontUrl`, y si falta, de
(`Origin` o `Referer`). Hay que publicar el backend.

# ANA — 2026-10-05 — Parque y sección sin preasignación

En venta de parque, parque y sección se guardan aunque no haya
preasignación. Cuadrante y espacio solo se guardan si está marcada.
Al generar la cotización en Odoo también se pasan parque y sección.

# ANA — 2026-10-05 — Bitácora por acción

El correo de firma, el pago, la venta nueva y la corrección quedan con
su acción. Un cambio de borrador guarda solo los campos que sí cambiaron.

# ANA — 2026-10-05 — Folio en todos los documentos

El folio de la cotización se sella en Drive al vincularla por el endpoint
y también cuando llega por sincronización. Entra en carátula, exclusiones,
reglamentos, autorización, nómina, carta de factura y consentimiento de
no factura. Antes de la cotización, los PDFs muestran el folio D-n.

# ANA — 2026-10-05 — Acceso de vendedor con contraseña

El administrador inicial (`ADMIN_USERNAME`) puede activar en configuración
una contraseña compartida. Con el flag apagado, el vendedor sigue con el
PIN de WhatsApp. `GET /auth/vendedor/modo-acceso` dice cuál flujo usar.

En producción, antes de desplegar:

`ALTER TABLE app_settings ADD COLUMN IF NOT EXISTS seller_password_login boolean NOT NULL DEFAULT false;`

`ALTER TABLE app_settings ADD COLUMN IF NOT EXISTS seller_access_password_hash text;`

`ALTER TABLE app_settings ADD COLUMN IF NOT EXISTS seller_access_password_expires_at timestamptz;`

La contraseña vence al final del día siguiente (zona de negocio). Si esa
fecha ya pasó, el login de vendedor vuelve al PIN de WhatsApp.

# ANA — 2026-10-05 — Corrección de INE

Odoo pide la INE como un solo documento. Al guardarla, el API exige
frente y reverso y deja cada lado en su archivo. Hay que actualizar
`sale_order_reception` (2.15).

# ANA — 2026-10-05 — Vendedor y jefe como texto

El listado de conciliación incluye `nombreJefeVentas`. Odoo guarda el
vendedor y ese jefe como texto, aparte del usuario de Odoo, y los muestra
en el expediente. La sincronización del expediente manda `vdSellerName` y
`vdManagerName`; `sellerName` sigue vacío para no cambiar el usuario de
Odoo. Al abrir el listado (vendedor o mesa) se reenvían las ventas que
aún no llevaron esos nombres. Hay que actualizar `sale_order_reception`
(2.16) y reiniciar el API.

# ANA — 2026-10-05 — Corrección por validar

Cuando el vendedor reenvía una corrección, la venta queda en
`PENDING_CORRECTION_REVIEW`. Al abrir el expediente, Odoo muestra el
archivo anterior y el nuevo. Aceptar actualiza el expediente y sigue el
flujo; rechazar regresa la venta a por corregir. Hay que actualizar
`sale_order_reception` (2.19) y reiniciar el API.

# ANA — 2026-10-05 — Corrección de todos los datos

El asistente de Odoo vuelve a listar los datos capturables de la venta
(contrato, contacto, factura, titular, beneficiarios, segundo contacto,
plan, pago) y los documentos que aplican. Hay que actualizar
`sale_order_reception` (2.20) y reiniciar el API.
